# AMGCReports frontend

The web app for AMGCReports: church workers file monthly pastoral reports (5 weeks × 21 metrics), and admins review, approve and export them. It talks to the Go API in `../backend`; every read and write goes through that API.

Next.js 16 (App Router, `cacheComponents`), React 19, TypeScript, Tailwind 4, shadcn/Radix and TanStack Query. Next.js 16 differs from older versions, so read `AGENTS.md` (generated by `next dev`) before using a Next.js API.

## Getting started

1. Start the API and its database (see `../backend`: `make db-start`, then `make dev`).
2. Copy `.env.example` to `.env.local` and set `NEXT_PUBLIC_API_URL` to the API's address.
3. Install and run:

```bash
npm install
npm run dev
```

Open [http://localhost:3000](http://localhost:3000) and sign in with an account from the API's seed data.

## Commands

| Task | Command |
|---|---|
| Dev server | `npm run dev` |
| Production build | `npm run build` |
| Lint / typecheck | `npm run lint` / `npm run typecheck` |
| Unit tests (Vitest) | `npm test` (`npm run test:cov` for coverage) |
| End-to-end (Playwright, with axe) | `npm run e2e` |
| Regenerate API types | `npm run gen:api` |

After a change to the API's Swagger annotations, run `make swagger` in `../backend` and then `npm run gen:api`. CI fails when `src/lib/api-types.ts` drifts.

## Layout

- `src/app/(app)/`: signed-in pages (reports, account, admin); each `page.tsx` renders one client screen beside it
- `src/components/`: shared components; `src/components/ui/` holds the shadcn primitives
- `src/lib/`: typed API clients per domain, the session, and the generated API types
- `e2e/`: Playwright specs

Deployed on Vercel. Project-wide docs live in `../docs/` (architecture, decisions, API reference).
